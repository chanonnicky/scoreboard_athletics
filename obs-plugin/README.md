# CG Live Native สำหรับ OBS

ปลั๊กอิน C++/Qt สำหรับทำ Bar/Lower Third ใน OBS โดยใช้ **Source เดียว** และควบคุมผ่าน **Dock ภาษาไทย**
ไม่ต้องเปิด `start.bat`, Python, PowerShell server, Browser Source หรืออินเทอร์เน็ตขณะใช้งาน
ระบบเว็บเดิมใน repository นี้ยังใช้งานแยกกันได้ตามเดิม ไม่มีการแชร์หรือย้ายข้อมูลโดยอัตโนมัติ

## ติดตั้ง

ปิด OBS ก่อนคัดลอกไฟล์ และเลือกแพ็กเกจให้ตรงระบบ/สถาปัตยกรรม ใช้แพ็กเกจแบบใดแบบหนึ่งเท่านั้นเพื่อไม่ให้โหลดปลั๊กอินซ้ำ

**Windows ปกติ** — แตก `cg-live-native-0.4.0-windows-x64.zip` แล้วนำโฟลเดอร์ `cg-live-native` ไปไว้ใน
`C:\ProgramData\obs-studio\plugins\` (อาจต้องสิทธิ์ Administrator)

```
C:\ProgramData\obs-studio\plugins\cg-live-native\
  bin\64bit\cg-live-native.dll
  data\fonts\...
```

**Windows Portable** — แตก `cg-live-native-0.4.0-windows-portable-x64.zip` ลงโฟลเดอร์ OBS Portable
ซึ่งมี `bin`, `data`, `obs-plugins` อยู่แล้ว ผลลัพธ์ต้องเป็น:

```
<OBS>\obs-plugins\64bit\cg-live-native.dll
<OBS>\data\obs-plugins\cg-live-native\fonts\...
```

**macOS** — เลือก ZIP `macos-arm64` สำหรับ Apple Silicon หรือ `macos-x86_64` สำหรับ Intel
แตกแล้วนำ `cg-live-native.plugin` ไปไว้ใน `~/Library/Application Support/obs-studio/plugins/`
แพ็กเกจเริ่มต้นใช้ ad-hoc signing และยังไม่มี Developer ID/notarization; เครื่องที่บังคับ Gatekeeper อาจต้องอนุญาตตามนโยบายของเครื่อง
ไม่ควรเปลี่ยนการตั้งค่าความปลอดภัยทั้งระบบเพื่อโหลดปลั๊กอิน

## ใช้งาน

1. เปิด OBS → **Docks → CG Live · Lower Third**
2. ไปหน้า **ตั้งค่า** เลือก Scene แล้วกด **เพิ่มลง Scene ปัจจุบัน** หรือเพิ่ม Source ชนิด **CG Live** เอง
3. หากต้องใช้ในหลาย Scene ให้ใช้ **Add Existing** เลือก CG Live เดิม ปุ่มเพิ่มใน Dock จะค้นหา Source เดิมและไม่เพิ่มรายการซ้ำใน Scene
4. กด **＋ สร้างรายการ** เพื่อเลือกประเภท ธีม รูป และแอนิเมชันในหน้า **ออกแบบ** แล้วกด **บันทึกคลัง**
5. หน้า **ใช้งาน**: เลือกชิ้นงาน → แก้ชื่อ/ข้อความในกรอบ **2 · แก้ข้อความก่อนขึ้นจอ** → กด **▶ ขึ้นรายการที่เลือก** โดยไม่ต้องสลับหน้า
6. ข้อความที่แก้เร็วมีผลเมื่อกดขึ้นจอเท่านั้น หากต้องการเก็บใช้ครั้งต่อไปให้กด **บันทึกข้อความ** การกดขึ้นจอไม่เขียนทับข้อความในคลังเอง
7. กด **ธีม / รูป / รูปแบบ** เพื่อเปิดหน้าออกแบบโดยนำข้อความที่กำลังเตรียมไว้ไปด้วย
8. ปุ่มลงข้างปุ่มขึ้นจอระบุชั้นของชิ้นงานที่เลือก เช่น **ลงแถบหลัก**; ปุ่ม **■ ลงจอทั้งหมด** อยู่ท้าย Dock ทุกหน้า
9. กด **ดูภาพออกอากาศ / ลงรายชั้น ▾** เพื่อขยาย Program preview และปุ่มลงแต่ละชั้น
10. หน้า **ตั้งค่า** รวมการเพิ่ม Source จัดลำดับ/ทำสำเนา/ลบรายการ นำเข้า/ส่งออกคลัง และ **ตัดจอทันที (ไม่เล่นแอนิเมชัน)**

หน้า **ใช้งาน** เปิดเป็นหน้าแรกและแสดงลำดับ **เลือกชิ้นงาน → แก้ข้อความ → ขึ้นจอ** ภาพ Program พับไว้เพื่อให้มีพื้นที่ทำงาน
คลิกหรือดับเบิลคลิกแถวเป็นการเลือกเท่านั้น ปุ่มสีเขียวเป็นคำสั่งขึ้นจอที่ชัดเจน
การปรับข้อความ/ธีม/โลโก้ **ไม่มีผลต่อภาพออกอากาศจนกดอัปเดต**
การโหลดรายการจากคลังไม่สั่งขึ้นจอเอง การทำสำเนาสร้าง ID ใหม่และไม่เปลี่ยนชิ้นที่กำลังออกอากาศ
ช่องข้อความและปุ่มใน Dock เพิ่ม padding สำหรับตัวอักษรไทย กราฟิกเพิ่มพื้นที่ว่างด้านข้างและบน–ล่าง
และจัดบรรทัดจากขอบเขต glyph ของฟอนต์จริง เพื่อให้สระ วรรณยุกต์ และตัวห้อยไม่ชิดขอบ

มีกราฟิก 6 แบบ: ชื่อ–ตำแหน่ง, หัวข้อ, ชื่อพร้อมรูป, แถบเต็มความกว้าง, แถบวิ่ง และโลโก้มุมจอ
แถบหลักแสดงได้ทีละชิ้น แต่แสดงร่วมกับแถบวิ่งและโลโก้ได้ รวมทั้งหมดใน Source เดียว
ลงจอรายชั้นได้ด้วยปุ่ม **ลงแถบหลัก / ลงแถบวิ่ง / ลงโลโก้** หรือใช้ **■ ลงจอทั้งหมด**

ธีมทั้ง 15 แบบวาดใหม่เป็น Native: Default, Glass, Clay, Clay Dark, Neumorphism, Retro,
Editorial, Asymmetrical, Bauhaus, Techno, Pop Art, Illustrative, Y2K, Swiss และ Pastel
สี `#e53935` เป็นค่าเริ่มต้นซึ่งใช้สีแนะนำของธีม; เลือกสีอื่นเพื่อ override สีเน้น
Glass ไม่เบลอภาพกล้องด้านหลัง โลโก้มุมจอแสดงรูปต้นฉบับโดยไม่เปลี่ยนสีตามธีม

ในหน้าออกแบบ กด **รูปลักษณ์ / แอนิเมชัน / เวลา** เพื่อปรับรายละเอียด:

- พื้นที่ออกแบบโปร่งใส 1920×1080; X/Y เป็นพิกัดมุมบนซ้ายของกราฟิก ปรับสเกลทั้ง Source ใน OBS ได้
- สีตัวอักษรตามธีม/สว่าง/เข้ม พื้นหลังตามธีม/ไล่สี/โปร่งใส/ไม่มีพื้น และความทึบทั้งชิ้น
- ฟอนต์ที่ติดตั้งในเครื่อง รวม Noto Sans Thai และ Charmonman ที่แถมมาแบบออฟไลน์
- แอนิเมชันเข้า/ออกเลือก **ตามธีม (แนะนำ)** หรือเลือกเอง: เข้า slide/fade/wipe/typewriter และออก **เลื่อนลง / จางออก / ปาดออก** ตั้งเวลาเข้าและออกแยกกันเป็น ms (`0` = ทันที)
- รายการใหม่ใช้แอนิเมชันตามธีม ค่าเริ่มต้น **เข้า 650 ms / ออก 420 ms** รายการเดิมคงตัวเลือกและเวลาเดิมไว้; คลังเก่าที่ไม่มีค่าออกยังใช้จางออก 300 ms
- ขณะลงจอมีสถานะ **↘ กำลังลง** กดลงซ้ำไม่เริ่มแอนิเมชันใหม่ กดขึ้นรายการใหม่แทนได้ทันที
- เริ่ม OBS, สลับ Scene Collection และนำเข้าคลังจะซ่อนทันทีเพื่อไม่พากราฟิกเก่าไปงานใหม่
- ตั้งเวลาลงจอเป็นวินาที (`0` = แสดงจนกดลงจอ) และความเร็วแถบวิ่งเป็นวินาทีต่อรอบ
- ข้อความยาวจะลดขนาดถึง 18 px แล้วตัดด้วยจุดไข่ปลา; ข้อความวิ่งรองรับหลายบรรทัดโดยคั่นเป็นข้อความต่อเนื่อง

### แอนิเมชันตามธีม (v0.3.0)

ในหน้า **ออกแบบ** เลือกธีมแล้วกด **ใช้แอนิเมชันตามธีม** เพื่อเลือก motion เข้า–ออกและเวลาแนะนำพร้อมกัน
กด **▷ ทดลองเข้า–ออก (ไม่ขึ้นจอจริง)** เพื่อเล่นตัวอย่างใน Preview เท่านั้น จากนั้นบันทึกคลังแล้วสั่งขึ้นจอเมื่อต้องการ
รายการที่เลือก “ตามธีม” จะเปลี่ยน motion ตามธีมให้อัตโนมัติ; ตัวเลือกแอนิเมชันแบบกำหนดเองยังใช้ต่อได้

| ธีม | ลักษณะการเคลื่อนไหว |
|---|---|
| Default | เลื่อนสั้นพร้อมเปิดแถบแบบ Broadcast |
| Glass | ลอยนุ่ม ขยายเล็กน้อย พร้อมแสงสะท้อนที่จำกัดอยู่บนตัวกราฟิก |
| Clay / Clay Dark | เด้งนุ่ม ยืด–หดเล็กน้อย และยุบตัวออก |
| Neumorphism | ยกตัวจากพื้นและค่อย ๆ จางออก |
| Retro | เปิดจากกึ่งกลาง พร้อมเส้นนีออนเคลื่อนที่ |
| Editorial | เปิด–ปิดแบบหน้ากระดาษ |
| Asymmetrical | เฉือนเปิดแนวทแยงและเลื่อนออกด้านข้าง |
| Bauhaus | เปิดเป็นบล็อกเรขาคณิตเรียงจังหวะ |
| Techno | เปิด–ปิดคมชัดพร้อมแถบสแกน |
| Pop Art | ป๊อปเด้งพร้อมเอียงเล็กน้อย |
| Illustrative | เผยและเก็บภาพแบบปาดพู่กัน |
| Y2K | ขยายตัวนุ่มพร้อมแสงเงาวาว |
| Swiss | เลื่อนและตัดเปิดอย่างแม่นยำ |
| Pastel | ลอยและละลายออกอย่างนุ่มนวล |

เอฟเฟกต์เหล่านี้ทำงานใน Native renderer รวมถึงโลโก้และแถบวิ่ง ไม่มีการกะพริบแบบสุ่มหรือ strobe
การทดลอง Preview ไม่เปลี่ยนภาพที่กำลังออกอากาศ และไม่บันทึกสถานะทดลองลงคลัง

Hotkey ตั้งที่ **OBS → Settings → Hotkeys → CG Live**: ขึ้นฉบับร่าง, ลงแถบหลัก, ลงจอทั้งหมด และขึ้นรายการ 1–20
ตำแหน่ง 1–20 อ้างอิงลำดับปัจจุบันในคลัง หากรายการนั้นยังไม่มี ปุ่มจะไม่สั่งขึ้นจอ

## คลังกลางและรูปภาพ

คลังและฉบับร่างใช้ร่วมกันทุก Scene Collection ของ OBS instance นี้
แต่ละ OBS Portable มี config ของตัวเอง จึงไม่แชร์ข้ามการติดตั้งโดยอัตโนมัติ
เริ่ม OBS และเปลี่ยน Scene Collection แล้วกราฟิกจะถูกซ่อนเสมอ

ตำแหน่งข้อมูลจริงแสดงที่ท้าย Dock ภายในโฟลเดอร์ config ของโมดูล `cg-live-native`:

```
library.json         # version 1: draft, items, hotkeys; ไม่มีสถานะ on-air
library.json.bak     # เวอร์ชันก่อนการบันทึกล่าสุด
library.json.damaged-*  # เก็บไฟล์เสียก่อนกู้คืน
assets/<sha256>.png  # รูปที่คัดลอกเข้าคลังของปลั๊กอิน
```

รูปที่เลือกจะถูกแปลงเป็น PNG จำกัดด้านยาว 2048 px (รองรับ PNG/JPEG/WebP/BMP ตาม image plugin ของ OBS)
เลือกภาพได้ไม่เกิน 40 ล้านพิกเซล ไม่มีการโหลดรูปจาก URL
หากไฟล์รูปหาย Dock จะแจ้งเตือนและไม่อนุญาตให้ขึ้นชิ้นนั้นจนเลือกรูปใหม่
ยังไม่มีการลบ assets อัตโนมัติ เพื่อรักษารูปที่แบบร่างหรือชิ้นออกอากาศยังอ้างอิง

ส่งออก `.cglive` เป็น JSON พร้อมรูป base64 ในไฟล์เดียว (สูงสุด 64 MB/1,000 รายการ)
การนำเข้าแทนที่คลัง/แบบร่างปัจจุบันหลังยืนยัน เก็บ hotkey ของเครื่องเดิม และซ่อนกราฟิกทั้งหมด
ตรวจ hash/ขนาด/ชื่อรูปและรูปแบบไฟล์ก่อนแทนที่คลัง; แพ็กเกจเสียจะไม่แทนที่รายการเดิม
ไม่รวมฟอนต์ระบบที่เลือกเพิ่มเอง ต้องติดตั้งฟอนต์เดียวกันในเครื่องปลายทาง
ไม่ควรเปิด OBS สอง instance ที่เขียน config เดียวกันพร้อมกัน

## Build และทดสอบ

ใช้ CMake 3.28+ (presets ต้อง 3.30+) และ Visual Studio C++ Build Tools พร้อม Windows SDK
หรือ Xcode บน macOS ดาวน์โหลด SDK/Qt จาก official OBS releases โดยตรวจ SHA-256 ตาม `buildspec.json`
SDK baseline คือ OBS 31.1.1 / Qt 6.8.3 ใช้เฉพาะ public API; เป้าหมายตรวจ runtime คือ OBS 32.1.2 และ 33.0.0
ไม่แจก Qt/OBS DLL มากับปลั๊กอิน และไม่ติดตั้งลง OBS ที่ใช้งานอยู่ให้อัตโนมัติ

```powershell
# Windows: ค้นหา VS 2022/2026 และ CMake ที่ติดมากับ Build Tools อัตโนมัติ
powershell -ExecutionPolicy Bypass -File obs-plugin/build.ps1
```

```bash
# macOS: build แต่ละสถาปัตยกรรมบน runner/เครื่องที่ตรงกัน
bash obs-plugin/build-macos.sh arm64
bash obs-plugin/build-macos.sh x86_64
```

สคริปต์จะ build → รัน tests → แพ็ก ZIP ใน `obs-plugin/dist/`
CI `.github/workflows/native-plugin.yml` ทำขั้นตอนเดียวกันบน Windows และ Mac ทั้งสองสถาปัตยกรรม
ต้องรัน CI บน GitHub จริงเพื่อยืนยันผล macOS; การมี workflow ไม่ถือว่าแพลตฟอร์มนั้นผ่านแล้ว

Tests ตรวจโมเดล/สำรองข้อมูล/แพ็กเกจ/ภาพ 90 คู่ประเภท–ธีม/alpha/กลุ่มอักขระไทย
และทดสอบปุ่ม Dock รวมการแยกแบบร่าง–ออกอากาศ คลังและการสั่งลงจอ
ภาพตรวจอยู่ใน `test-output/themes.png` และ `test-output/dock.png`
ตัวเลข CPU compositor ใน test ไม่รวม GPU upload และไม่ใช่ผลยืนยันประสิทธิภาพ broadcast 1080p60

มี `cg-native-smoke` และ `cg-obs-tests` สำหรับตรวจการโหลดโมดูลและ readback จาก GPU กับ libobs ของ OBS จริง
โมดูลทดสอบนี้ไม่ถูกติดตั้งหรือรวมใน ZIP ดูคำสั่งรัน/ผลจริงใน `VALIDATION.md`

ก่อนเผยแพร่ต้องตรวจบน OBS เป้าหมาย: Dock จริง, hotkey, Studio Mode, เพิ่ม Source เดิมหลาย Scene,
เปลี่ยน Collection, ปิด–เปิด OBS, alpha บนภาพสว่าง/มืด, แถบวิ่งพร้อมแอนิเมชันที่ 1080p60 และการถอนปลั๊กอิน
ใช้ OBS log ตรวจข้อความ `[CG Live]` หากโหลดไม่ได้
